## 🔴 LE PLUS URGENT — Sécurité Supabase (vérifié en prod)

Projet actif : **Graillman's Project** (`klejwxhvmxhmuvcyolwv`, eu-north-1). RLS est *activé* mais les policies sont **grandes ouvertes** (confirmé par les advisors Supabase) :

| Table / fonction | Policy | Problème |
|---|---|---|
| `saved_wheels` | INSERT `WITH CHECK (true)` | 🔴 N'importe qui insère n'importe quoi, sans limite |
| `saved_wheels` | UPDATE `USING (true)` | 🔴 N'importe qui peut **réécrire/écraser les 17 roues existantes** (titre, items, auteur) |
| `spin_counter` | UPDATE `USING (true)` | 🟠 N'importe qui réécrit le compteur global affiché en preuve sociale |
| `increment_spins(amount)` | SECURITY DEFINER, exécutable par `anon`, `amount` contrôlé client, `search_path` mutable | 🟠 `rpc('increment_spins',{amount:1e12})` fausse le compteur définitivement |

**Exploitation** : la clé anon est dans le bundle JS public (normal), donc tout repose sur les RLS. Or ici un attaquant ouvre la console (ou curl) et peut : spammer la galerie, **vandaliser les roues publiques existantes** (injection de spam/liens dans les 17 roues), et fausser tous les compteurs.

**Correctifs (SQL, prioritaires) :**
1. `saved_wheels` UPDATE : supprimer la policy `update wheels` ouverte. Les utilisateurs anonymes ne doivent **jamais** pouvoir modifier une roue existante. Si l'incrément de `spin_count` est nécessaire, le faire via une fonction RPC dédiée bornée (+1 fixe).
2. `saved_wheels` INSERT : remplacer `WITH CHECK (true)` par des contraintes —
   ```sql
   WITH CHECK (
     char_length(title) <= 80
     AND array_length(items,1) BETWEEN 2 AND 200
     AND is_public = true
   )
   ```
   + `CHECK` constraints en base sur la longueur de chaque item, + rate-limit (Cloudflare Turnstile ou edge function par IP).
3. `spin_counter` : supprimer l'UPDATE ouvert ; ne passer que par `increment_spins`.
4. `increment_spins` : forcer `+1` côté SQL (ignorer/borner `amount BETWEEN 1 AND 100`), ajouter `SET search_path = ''`, et `REVOKE EXECUTE` pour `authenticated` si inutile.
5. ⚠️ **Le projet "Realwheelpicker" (eu-west-1) est INACTIVE/en pause** — vérifier lequel pointe réellement la prod (`PUBLIC_SUPABASE_URL`). Le site utilise visiblement "Graillman's Project". Nettoyer le projet mort pour éviter la confusion.

## ⚡ PERFORMANCE & FLUIDITÉ

Le **moteur de la roue est excellent** (Canvas 2D, dpr capé à 1, redraw throttlé ~30fps en bypass React, easing pré-instancié, rAF nettoyés, `prefers-reduced-motion` respecté). Images/fonts/CSS propres. **Tout le gain est sur le JS chargé en amont.**

| # | Sévérité | Problème | Fichier | Gain |
|---|---|---|---|---|
| P1 | 🔴 | `i18n.ts` (286 Ko, 6 langues) finit **dans le bundle client** via `LanguageContext` → `HeaderIsland` (`client:load`, toutes les pages). Chunk = **75 Ko gzip sur 156 pages**. Une page FR embarque ES/DE/IT/PT inutilement. | `src/lib/i18n.ts:517`, `LanguageContext.tsx:3`, `HeaderIsland.tsx:4` | **−60 à −75 Ko gzip** |
| P2 | 🔴 (prod) | `@supabase/supabase-js` (44 Ko gzip) chargé sur accueil + 153 pages SEO **juste pour un compteur de spins**, via `useSpinCounter`. | `spinCounter.ts:1`, `supabase.ts` | **−44 Ko gzip** |
| P3 | 🟠 | `HeaderIsland` en `client:load` sur ~308 pages : header quasi statique (liens `<a>`), bloque le main thread (INP/LCP) et provoque un **flash de langue** (EN→langue page) sur les pages non-EN. | `HeaderIsland.tsx`, `LanguageContext.tsx:37` | INP/LCP |
| P4 | 🟡 | `useSpinCounter` fait un `setInterval` réseau Supabase **toutes les 30 s** sur 154 pages même sans spin. | `useSpinCounter.ts:32` | CPU/batterie |
| P5 | ⚪ | `AdPlaceholder` (rend `display:none`) hydraté en îlot vide ×142 ; `GlobalFooterIsland` incohérent (`client:load` vs `client:idle`) ; dépendance `canvas-confetti` peut-être morte (composant maison utilisé). | `AdPlaceholder.tsx:17` | nettoyage |

**JS accueil ≈ 188 Ko gzip** (hors Supabase), dominé à 40 % par i18n.

**Solution i18n recommandée (la plus propre pour un site mono-langue-par-URL)** : passer le dictionnaire de la seule langue de la page en **prop** depuis le `.astro` vers l'îlot (`<HeaderIsland t={translations[lang]} client:load />`). Le `.astro` reste serveur, `i18n.ts` n'est plus importé dans aucun `.tsx`. Élimine P1 *et* le flash de langue P3. Alternative : JSON par locale + `import()` dynamique.

bon à savoir : `lucide-react` est bien tree-shaké (import par icône), radix peu présent dans le bundle réel.

## 🏗️ ARCHITECTURE, QUALITÉ, ACCESSIBILITÉ, PRODUIT

### Accessibilité — point le plus faible (la roue est inaccessible)
- 🟠 **A11Y1** — Le `<canvas>` de la roue n'a ni `role`, ni `aria-label`, ni alternative DOM. Invisible aux lecteurs d'écran (`SpinningWheel.tsx:908`).
- 🟠 **A11Y2** — **Le gagnant n'est jamais annoncé** : aucune région `aria-live`/`role="status"` dans le flux de tirage. Le résultat — la fonction même de l'outil — est inaccessible en non-visuel (`WinnerResult.tsx`).
- 🟠 **A11Y3** — **Pas de pilotage clavier** sur les pages sans bouton central : le canvas se lance via `onClick`/`onTouch` sans `tabIndex`/`onKeyDown` (`SpinningWheel.tsx:918`).
- 🟡 **A11Y4** — Label Spin codé en dur en anglais (`aria-label="Spin the wheel"`, `SPIN`, `tap to play`) même sur `/tirage-au-sort` FR (`SpinningWheel.tsx:943`).
- ✅ Bons points : skip link, breadcrumb `aria-label`, boutons toolbar de `SimpleWheelIsland` bien labellisés.

### Qualité / dette
- 🟠 **Q1** — Logique d'îlot dupliquée (copier-coller) entre `HomepageIsland` (794 l.), `WeightedPickerProIsland` (699 l.), `SocialGiveawayIsland` (657 l.), etc. : mêmes `handleDraw`/`handleComplete`/`handleShare`/sound/theme/history répliqués 5-7×. → extraire un hook `useWheelController`. (la roue `SpinningWheel` elle est bien réutilisée ✅)
- 🟠 **Q2** — **~50 pages standalone dupliquent toute la structure** (JSON-LD + sections + FAQ inline). Le pattern propre existe (`[slug].astro` + `seoPageConfig.ts` + `SEOPageIsland`, 21 pages) mais n'est pas généralisé. → migrer les standalone vers `seoPageConfig`.
- 🟡 **Q3** — Deux systèmes de partage d'URL **incompatibles** : `useShareableURL.ts` (`?entries=`, casse les pseudos avec virgule, pas de borne) vs `wheelShare.ts` (`#w=`, robuste, borné). → unifier sur `wheelShare`.
- 🟡 **Q4** — Build sans `astro check` ni lint des `.astro` → erreurs TS n'arrêtent pas le build, JSX inline des pages non vérifié.
- 🟡 **Q5** — **Aucun test** (0 vitest/playwright). Pour un outil dont le cœur est la *fairness* du tirage, l'absence de tests sur `cryptoRandom`/`weightedRandom`/sélection multi-gagnants est le risque de régression #1.
- ⚪ **Q6** — Pas d'`ErrorBoundary` : un crash d'îlot fait disparaître tout le contenu. Type `Participant` redéfini ×7. Clés localStorage en dur dispersées (`rwp:` vs `realwheelpicker_`). `yearlyCount` surcompte transitoirement.
- ✅ Bons points : RNG crypto honnête, roue honnête (winner = slice réelle), dégradation gracieuse sans Supabase, dark mode réel, hydratation i18n documentée, `any`/`@ts-ignore` quasi absents.

### Manques produit (vs wheelofnames.com) — priorisés
- **P0** : Sauvegarde de listes nommées (récurrent pour profs/streamers) · Export du résultat (PNG/CSV, preuve) · Accessibilité (cf. ci-dessus).
- **P1** : Import CSV généralisé (existe mais branché que sur certains îlots) · Multi-gagnants exposé partout (forcé à 1 sur `SimpleWheelIsland`) · Sons personnalisables.
- **P2** : PWA/offline (quasi gratuit, site 100% client-side, manifest absent) · Undo · Image OG dynamique du gagnant pour le partage social.
